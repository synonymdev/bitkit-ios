# Hardware wallet

Pairing and using Trezor and Blockstream Jade devices as watch-only wallets: connect sheet, passphrase wallets, home tile and detail screen, settings, receive tab, on-chain send, transfer to spending, and the dev Trezor screen. Activity rows of these wallets are in `activity.md`; the generic transfer flow is in `transfer.md`.

## What it does
- Pairs a device over Trezor Bridge (`TrezorBridgeTransport`, debug/E2E builds only), Trezor BLE (`TrezorBLEManager`) or Jade BLE (`JadeBLEManager`). `HwWalletVendor` has `trezor` and `blockstream` (Jade); every device call is routed by the vendor stored on the wallet.
- `HwWalletManager` keeps one wallet per identity (a Trezor with passphrase protection yields its standard wallet plus one wallet per hidden passphrase), runs one xpub watcher per (wallet, address type), aggregates balance, and persists on-chain activity into bitkit-core under the wallet's `walletId` (`HwWalletId`, e.g. `trezor:<hex>`). Only one vendor holds a session at a time.
- Connect phases (`HwConnectViewModel.Phase`): intro, searching, found, paired (editable "Label Funds"), passphrase, passphrasePaired, pairCode (Trezor THP pairing code). Jade waiting for PIN shows `HwFoundUnlockHint`.
- Passphrase wallet: entering a passphrase at Paired opens the hidden wallet as its own identity; a duplicate is rejected inline (`HwPassphraseError`). Transfer signing asks for the passphrase again when the session is gone (`HwPassphrasePromptSheet`) and refuses a passphrase that opens a different wallet (`TransferViewModelHwTests`, `passphrase-transfer-to-spending.xml`). The journeys scan the app group for the passphrase text (leak check).
- Home tile `ActivityHardware` (`HardwareWalletsGrid`): name, connection badge, balance. Tile opens `HardwareWalletScreen` (balance, `HardwareTransferToSpending`, activity list, remove).
- Receive: the Receive sheet gains a hardware tab (label from `HwWalletVendor.modelName`) with a watcher address and `HardwareVerifyAddress` (on-device verification).
- Send: the Send amount screen can switch the funding source to a hardware wallet (`AssetButton-switch`); signing happens on `HwSendSignView`. RBF/boost is disabled for hardware activity (no keys).
- Transfer to spending from a hardware wallet: amount (`SpendingAmountHw`) -> sign (`SpendingHwSign`, creates the Blocktank order on `HardwareTransferOpenTrezorConnect`) -> signed (`SpendingHwSigned`, auto-forwards) -> `SettingUpView`. Uses native segwit account only (`hwFundingDefaultAddressType`); `HwFundingSigner` computes limits and fee reserve.
- Remove: `RemoveHwWalletDialog` with toggle `HwRemoveKeepBackupToggle` ("Back up name and tags", `keepBackupData` into `removeWallet`); paired devices persist in `HwKnownDeviceStorage`; Trezor credentials live in the Keychain (service `to.bitkit.trezor.thp`, per `journeys/hardware-wallet/README.md`).
- Not hardware wallets: `WatchOnlyAccountsView` / `WatchOnlyAccountService` (Settings > Advanced) hold per-Paykit-server accounts (string `watch_only_accounts__description`), see `journeys/pubky-auth`.

## How a user reaches it
- Connect sheet (`SheetID.hardwareConnect`): home suggestion card `Suggestion-hardware` (`SuggestionAction.hardware`) or Settings > General `HardwareWalletsSettings` (`GeneralSettingsView`) > `HardwareWalletsScreen` > `AddHardwareWallet`.
- Sheet ids: `HardwareWalletIntroScreen` (`HardwareWalletIntroContinue`, `HardwareWalletIntroCancel`) > `HardwareWalletSearchingScreen` (`HardwareWalletSearchingCancel`, `HardwareWalletSearchingError`) > `HardwareWalletFoundScreen` (`HardwareWalletFoundConnect`, `HardwareWalletFoundCancel`, `HwFoundError`) > `HardwareWalletPairedScreen` (`HardwareWalletLabelInput`, `HardwareWalletPairedFinish`, `HardwareWalletPairedPassphrase`) > `HardwareWalletPassphraseScreen` (`HardwareWalletPassphraseInput`, `HardwareWalletPassphraseContinue`, `HardwareWalletPassphraseBack`) > `HardwareWalletPassphrasePairedScreen`. Pair code: `HardwareWalletPairCodeScreen`; app-wide pairing sheet `SheetID.hardwarePairing` (`HwPairSheet`).
- Settings rows: `HardwareWalletRow_<id>`, tap name `HardwareWalletRowName<id>` (no separator) opens `SheetID.renameHardwareWallet` (`RenameHardwareWalletInput`, `RenameHardwareWalletSave`), trash `HardwareWalletRowDelete_<id>` opens `RemoveHwWalletDialog` (`DialogConfirm`, `DialogCancel`). `<id>` is the full wallet id.
- Detail screen: tile `ActivityHardware` > `HardwareWalletScreen`: `HardwareTransferToSpending`, `RemoveHardwareWallet`, rows `Activity-<index>`. Route `Route.hardwareWallet(walletId:)`.
- Transfer: `SpendingIntro-button` (route `spendingIntroHw`) > `HardwareTransferAmount` (`HardwareTransferAmountAvailable`, `HardwareTransferAmountQuarter`, `HardwareTransferAmountMax`, `HardwareTransferAmountContinue`, toast `HardwareTransferAmountExceededToast`) > `HardwareTransferSign` (`HardwareTransferOpenTrezorConnect`, `HardwareTransferSignLearnMore`, `HardwareTransferSignAdvanced`/`HardwareTransferSignDefault`) > `HardwareTransferSigned` > `LightningSettingUp`/`TransferSuccess`. Passphrase prompt: `HwTransferPassphraseSheet` (`HwTransferPassphraseInput`, `HwTransferPassphraseContinue`, `HwTransferPassphraseCancel`).
- Send: tab bar `Send` > `RecipientManual` > `RecipientInput` > `AddressContinue` > `SendAmount` (`AssetButton-switch`; id suffix is `switch` when more than one source, else `spending`/`savings`/`trezor`) > `SendConfirm` > `GRAB` > `HardwareSendSign` (`HardwareSendOpenTrezorConnect`) > `SendSuccess`.
- Receive: `Receive` > tab `Tab-trezor` (Jade: `Tab-jade`) > `HardwareVerifyAddress`.
- Dev Trezor screen: Settings > Advanced > `DevSettings` > row `Trezor` (`TrezorRootView`): `TrezorScanButton`, `TrezorDevice-bridge`, `TrezorKnownDeviceConnect-bridge`, `TrezorForgetDevice-bridge`, `TrezorDisconnectButton`, `TrezorSection-DeviceInfo`, test hooks `TrezorTestHook-Pin|Passphrase|Pairing|Confirm`. Dev Settings shows in Debug builds (`showDevSettings` default `Env.isDebug`).

## How to drive it
- Journeys `journeys/hardware-wallet/` (README: `journeys/hardware-wallet/README.md`): `connect-home-tile.xml` ("Hardware Wallet Connect and Home Tile"), `settings-hardware-wallets.xml` ("Hardware Wallet Settings"), `connect-flow.xml` ("Hardware Wallet Connect Flow From Settings"), `suggestion-intro-sheet.xml` ("Hardware Wallet Suggestion Card and Intro Sheet"), `reconnect.xml` ("Hardware Wallet Reconnect"), `detail-overview.xml` ("Hardware Wallet Detail Overview"), `activity-blue-icons.xml`, `activity-detail-hw-tags.xml`, `transfer-to-spending.xml`, `transfer-to-spending-max-lsp-cap.xml`, `transfer-to-spending-node-warmup.xml`, `transfer-to-spending-over-max.xml` ("hardware transfer to spending amount over max is blocked"), `send-onchain.xml` ("Hardware Wallet Send On-chain"), `passphrase-pairing.xml`, `passphrase-duplicate.xml`, `passphrase-transfer-to-spending.xml`, `passphrase-settings-remove.xml`.
- Order (README): `connect-home-tile` first; then settings/connect/suggestion; then activity, transfer, reconnect, send; then passphrase 4 in order; `detail-overview` last (it forgets the device).
- Setup: `bitkit-docker` `docker compose up -d` then `./scripts/trezor-emulator start` (passphrase journeys: `TREZOR_PASSPHRASE_PROTECTION=true`); build with `E2E_BUILD`, `TREZOR_BRIDGE=true`, `TREZOR_BRIDGE_URL=http://127.0.0.1:21325`; do not add `TEST_TREZOR_EMU`. Approve prompts with `../bitkit-docker/scripts/trezor-emulator send-json '{"type":"emulator-press-yes","id":1}'`. Send and transfer need funds in the emulator account and regtest Blocktank for the transfer.
- E2E `bitkit-e2e-tests/test/specs/hardware-wallet.e2e.ts`, describe `@hardware_wallet @ios_gate` (iOS Mini only; Android staging uses `@hardware_wallet`): `@hardware_wallet_1` connect/rename/remove via suggestion, `_2` receive to hardware, `_3` transfer to spending, `_4` send on-chain with tag. Helpers `bitkit-e2e-tests/test/helpers/hardware-wallet.ts` start the emulator through `bitkit-e2e-tests/scripts/trezor-emulator` (`ensureTrezorEmulator({fresh:true})`) and press Yes via `send-json`. Build: `TREZOR_BRIDGE=true ./scripts/build-ios-sim.sh` (+ `BACKEND=regtest` for staging); the app's `e2e-tests.yml` build also passes `TREZOR_BRIDGE=true`; `BACKEND=local` has no Blocktank (spec skips the spending-balance check).
- UI tests (AI-only, `docs/AI_DEVICE_TESTS.md`, git path `Docs/AI_DEVICE_TESTS.md`): `BitkitUITests/TrezorBridgeDashboardUITests.swift` via scheme `BitkitAITests` with `TEST_TREZOR_EMU=1`, `TEST_TREZOR_RESET_STATE=1`, `TREZOR_BRIDGE=true`, `TREZOR_ELECTRUM_URL=tcp://127.0.0.1:60001`; CI `.github/workflows/ai-device-tests.yml` (manual, suite `trezor-emu`). With `TEST_TREZOR_EMU` the app shows `TrezorRootView` instead of the wallet (`AppScene.mainContent`).

## What proves it
- Connect: `HardwareWalletPairedScreen` then, after Finish, `ActivityHardware` shows the label (e2e `expectText(label)`); Suggestion card disappears (`Suggestion-hardware` hidden); Settings row lists the label with a green badge.
- Rename/remove: renamed label on the tile; after `DialogConfirm` the label and `ActivityHardware` are gone.
- Receive: `ActivityHardware` amount equals the funded sats; hardware screen `Activity-1` shows "Received" and the amount; savings/spending stay 0.
- Transfer: `HardwareTransferSigned`, then `LightningSettingUp`/`TransferSuccess`; hardware balance drops (`condition: 'lt'`); on regtest the spending balance goes above 0; journey checks one blue Transfer row "From Savings" with "TO SPENDING" in detail.
- Send: `SendSuccess` (amount 10 000 in the journey); hardware screen shows one outgoing row and a lower tile balance; tag `Tag-hwsend-delete` visible on the row detail.
- Passphrase: second tile with the hidden label, headline total at least the sum; duplicate shows `HwPassphraseError`; leak scan prints `NO_PASSPHRASE_LEAK`.
- Dev screen UI tests: `TrezorConnectedView`, bridge address starts `bcrt1`, signature valid, `TrezorBroadcastTxid` non-empty, debug log has no mnemonic or "passphrase".

## Gotchas
- Journeys that pair, re-pair or reconnect need the Bridge build; read-only journeys run on a plain build. In bridge mode `TrezorManager.setup` skips starting CoreBluetooth and `JadeTransport` skips the Jade scan, so no Bluetooth dialog.
- Identifier quirk: `HardwareWalletRowName<id>` has no separator, `HardwareWalletRowDelete_<id>` and `HardwareWalletRow_<id>` use `_`.
- Intro headline renders uppercase ("ADD YOUR HARDWARE WALLET"); settings has no Payments section (flat General list, `Tab-general`).
- Emulator prompts block until acknowledged, once per address type for a passphrase session; the e2e helper polls `emulator-press-yes` every 500 ms (timeout 180 s).
- Grep the app group (not `os_log`) for leaks, and treat only grep exit status 1 as clean (README).
- Two `trezor-emulator` scripts exist: `bitkit-docker/scripts/trezor-emulator` (journeys) and `bitkit-e2e-tests/scripts/trezor-emulator` (e2e).
- `SpendingAmountHw` once left the pad uncapped when limits were already computed (fixed in #686; regression journey `transfer-to-spending-over-max.xml` enters the screen twice).
- The Trezor image is pinned in the e2e docker compose to keep the Bridge raw message format (e2e README).
- Receive tab id is `Tab-trezor`/`Tab-jade` on iOS; Android uses `Tab-hardware` (e2e helper tries both).
